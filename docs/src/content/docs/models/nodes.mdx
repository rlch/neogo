Nodes are the fundamental building blocks of a Neo4j graph. In neogo, you define nodes as Go structs that embed `neogo.Node`.

## Basic Node Definition

To define a node, create a struct that embeds `neogo.Node` with a label tag:

```go
import "github.com/rlch/neogo"

type Person struct {
    neogo.Node `neo4j:"Person"`

    Name string `neo4j:"name"`
    Age  int    `neo4j:"age"`
}
```

The `neo4j:"Person"` tag on the embedded type defines the Neo4j label for this node.

## Node Base Type

The `neogo.Node` type provides:

```go
type Node struct {
    ID string `neo4j:"id"`
}

func (n *Node) IsNode()
func (n Node) GetID() string
func (n *Node) SetID(id any)
func (n *Node) GenerateID()  // Generates a ULID
```

Use `GenerateID()` to create unique IDs:

```go
person := Person{Name: "Alice", Age: 30}
person.GenerateID()  // person.ID is now a ULID like "01J5ABCD..."
```

## Properties with Tags

Use the `neo4j` tag to map struct fields to Neo4j properties:

```go
type Person struct {
    neogo.Node `neo4j:"Person"`

    // Maps to "name" property
    Name string `neo4j:"name"`

    // Maps to "birth_date" property
    BirthDate time.Time `neo4j:"birth_date"`

    // Skipped - not stored in Neo4j
    Internal string `neo4j:"-"`

    // Optional property (pointer type)
    Nickname *string `neo4j:"nickname"`
}
```

## Multiple Labels

A node can have multiple labels by listing them in the tag:

```go
type Employee struct {
    neogo.Node `neo4j:"Person,Employee"`

    Name       string `neo4j:"name"`
    EmployeeID string `neo4j:"employee_id"`
}
```

This creates nodes with both `:Person` and `:Employee` labels.

## Label Inheritance via Embedding

Use Go's struct embedding for label hierarchies:

```go
type Person struct {
    neogo.Node `neo4j:"Person"`
    Name string `neo4j:"name"`
}

type Employee struct {
    Person                          // Inherits Node and Person label
    neogo.Node `neo4j:"Employee"` // Adds Employee label
    EmployeeID string `neo4j:"employee_id"`
}
```

<Aside type="tip">
Embedding allows you to query for all `Person` nodes while getting both `Person` and `Employee` results.
</Aside>

## Using Nodes in Queries

Write raw Cypher with your node labels and bind results to your structs:

```go
var person Person

// Query a single node
err := driver.Exec().
    Cypher(`MATCH (p:Person {name: $name}) RETURN p`).
    RunWithParams(ctx, map[string]any{"name": "Alice"}, "p", &person)

// Query multiple nodes
var people []Person
err := driver.Exec().
    Cypher(`MATCH (p:Person) WHERE p.age > $minAge RETURN p`).
    RunWithParams(ctx, map[string]any{"minAge": 18}, "p", &people)
```

## Creating Nodes

Create nodes with Cypher and parameters:

```go
person := Person{Name: "Alice", Age: 30}
person.GenerateID()

err := driver.Exec().
    Cypher(`CREATE (p:Person {id: $id, name: $name, age: $age})`).
    RunWithParams(ctx, map[string]any{
        "id":   person.ID,
        "name": person.Name,
        "age":  person.Age,
    })
```

Or create and return:

```go
err := driver.Exec().
    Cypher(`
        CREATE (p:Person {id: $id, name: $name, age: $age})
        RETURN p
    `).
    RunWithParams(ctx, map[string]any{
        "id":   person.ID,
        "name": person.Name,
        "age":  person.Age,
    }, "p", &person)
```

## Querying Properties

Query specific properties:

```go
var name string
var age int64

err := driver.Exec().
    Cypher(`MATCH (p:Person {id: $id}) RETURN p.name, p.age`).
    RunWithParams(ctx, map[string]any{"id": "person-123"},
        "p.name", &name,
        "p.age", &age)
```

## Schema Tags

Add indexes and constraints via tags:

```go
type Person struct {
    neogo.Node `neo4j:"Person"`

    Email string `neo4j:"email,unique"`     // Unique constraint
    Name  string `neo4j:"name,index"`       // Range index
    Bio   string `neo4j:"bio,fulltext"`     // Fulltext index
    Age   int    `neo4j:"age,notNull"`      // Not null constraint
}
```

Then auto-migrate:

```go
actions, err := driver.Schema().AutoMigrate(ctx)
```

See [Schema Migration](/schema/migration/) for details.

## Best Practices

1. **Always embed `neogo.Node`**: Provides ID management and interface compliance
2. **Use explicit tags**: Explicit property names prevent issues with Go naming changes
3. **Generate IDs before create**: Use `GenerateID()` for unique identifiers
4. **Register types**: Use `neogo.WithTypes()` when creating the driver
5. **Add schema tags**: Define indexes/constraints at the type level
