Abstract nodes allow you to define a common interface for multiple node types, enabling polymorphic queries. This is useful when different node types share common properties.

## The Problem

In Neo4j, you might have multiple node types that share common properties:

```cypher
(:Person {name: "Alice", age: 30})
(:Company {name: "Acme Corp", founded: 1990})
(:Product {name: "Widget", price: 99.99})
```

All have a `name` property, but are different types. How do you query all "nameable" things and deserialize them into the correct Go types?

## Defining Abstract Nodes

An abstract node embeds `neogo.Abstract` and implements the `Implementers()` method:

```go
import "github.com/rlch/neogo"

// Abstract node - defines shared properties
type Named interface {
    neogo.IAbstract
    GetName() string
}

// Base struct for all Named implementers
type NamedBase struct {
    neogo.Abstract `neo4j:"Named"`
    Name string `neo4j:"name"`
}

func (n NamedBase) GetName() string { return n.Name }

func (n *NamedBase) Implementers() []neogo.IAbstract {
    return []neogo.IAbstract{
        &Person{},
        &Company{},
        &Product{},
    }
}
```

## Concrete Implementations

Each concrete type embeds the abstract base and adds its own label:

```go
type Person struct {
    NamedBase               // Embeds Named properties
    neogo.Node `neo4j:"Person"`
    Age int `neo4j:"age"`
}

type Company struct {
    NamedBase               // Embeds Named properties
    neogo.Node `neo4j:"Company"`
    Founded int `neo4j:"founded"`
}

type Product struct {
    NamedBase               // Embeds Named properties
    neogo.Node `neo4j:"Product"`
    Price float64 `neo4j:"price"`
}
```

<Aside type="tip">
All implementers should include a shared label (like "Named") plus their specific label (like "Person").
</Aside>

## Registering Abstract Types

Register abstract types and their implementers:

```go
driver, err := neogo.New(
    "neo4j://localhost:7687",
    neo4j.BasicAuth("neo4j", "password", ""),
    neogo.WithTypes(
        &NamedBase{},  // Register abstract
        &Person{},     // Register implementers
        &Company{},
        &Product{},
    ),
)
```

## Querying Abstract Nodes

When you query the abstract type, neogo deserializes into the correct concrete type based on labels:

```go
// Query all Named nodes
var results []Named

err := driver.Exec().
    Cypher(`MATCH (n:Named) RETURN n`).
    Run(ctx, "n", &results)

for _, named := range results {
    switch v := named.(type) {
    case *Person:
        fmt.Printf("Person: %s, age %d\n", v.Name, v.Age)
    case *Company:
        fmt.Printf("Company: %s, founded %d\n", v.Name, v.Founded)
    case *Product:
        fmt.Printf("Product: %s, price $%.2f\n", v.Name, v.Price)
    }
}
```

## Label-Based Discrimination

neogo uses Neo4j labels to determine which concrete type to instantiate:

1. neogo fetches the node's labels from Neo4j
2. It checks each implementer's labels
3. It instantiates the implementer whose labels best match

```go
// If Neo4j returns labels: ["Named", "Person"]
// neogo will instantiate a *Person

// If Neo4j returns labels: ["Named", "Company"]
// neogo will instantiate a *Company
```

## Abstract Nodes in Relationships

Abstract nodes work in relationship queries:

```go
type Person struct {
    NamedBase
    neogo.Node `neo4j:"Person"`
    Age int `neo4j:"age"`
}

// Query: What does each person own?
var person Person
var owned []Named  // Could be Company, Product, etc.

err := driver.Exec().
    Cypher(`
        MATCH (p:Person {id: $id})-[:OWNS]->(o:Named)
        RETURN p, collect(o) AS owned
    `).
    RunWithParams(ctx, map[string]any{"id": personID},
        "p", &person,
        "owned", &owned)

// Each item in 'owned' is the correct concrete type
for _, item := range owned {
    switch v := item.(type) {
    case *Company:
        fmt.Printf("Owns company: %s\n", v.Name)
    case *Product:
        fmt.Printf("Owns product: %s ($%.2f)\n", v.Name, v.Price)
    }
}
```

## Common Patterns

### Union Types

```go
// SearchResult could be any searchable entity
type Searchable interface {
    neogo.IAbstract
    GetID() string
}

type SearchableBase struct {
    neogo.Abstract `neo4j:"Searchable"`
}

func (s *SearchableBase) Implementers() []neogo.IAbstract {
    return []neogo.IAbstract{
        &Person{},
        &Article{},
        &Comment{},
    }
}
```

### Soft Interfaces (Auditable)

```go
// Auditable tracks creation/modification
type Auditable interface {
    neogo.IAbstract
    GetCreatedAt() time.Time
}

type AuditableBase struct {
    neogo.Abstract `neo4j:"Auditable"`
    CreatedAt time.Time `neo4j:"created_at"`
    UpdatedAt time.Time `neo4j:"updated_at"`
    CreatedBy string    `neo4j:"created_by"`
}

func (a AuditableBase) GetCreatedAt() time.Time { return a.CreatedAt }

func (a *AuditableBase) Implementers() []neogo.IAbstract {
    return []neogo.IAbstract{
        &Document{},
        &User{},
        &Setting{},
    }
}
```

## Best Practices

<Aside type="tip" title="Design Tips">

1. **Keep abstract nodes focused**: Include only truly shared properties
2. **Use meaningful base labels**: The abstract label should describe the shared trait
3. **Register all implementers**: Missing implementers will cause deserialization errors
4. **Consider using interfaces**: Go interfaces make abstract patterns more idiomatic

</Aside>
