neogo uses Go struct tags to control how fields are serialized to Neo4j properties and how schema elements like indexes and constraints are created.

## The `neo4j` Tag

The primary tag for neogo is `neo4j`. It's used both on embedded types (for labels/types) and on fields (for property names and schema).

### On Embedded Types

Defines labels for nodes and types for relationships:

```go
// Single label
type Person struct {
    neogo.Node `neo4j:"Person"`
}

// Multiple labels
type Employee struct {
    neogo.Node `neo4j:"Person,Employee"`
}

// Relationship type
type Knows struct {
    neogo.Relationship `neo4j:"KNOWS"`
}
```

### On Fields

Maps struct fields to Neo4j properties:

```go
type Person struct {
    neogo.Node `neo4j:"Person"`

    // Maps to "name" property
    Name string `neo4j:"name"`

    // Maps to "birth_date" property
    BirthDate time.Time `neo4j:"birth_date"`

    // Skip this field
    Internal string `neo4j:"-"`
}
```

## Property Tag Options

| Tag | Description |
|-----|-------------|
| `neo4j:"name"` | Property name in Neo4j |
| `neo4j:"-"` | Skip this field |
| `neo4j:"name,index"` | Add range index |
| `neo4j:"name,unique"` | Add unique constraint |
| `neo4j:"name,notNull"` | Add not-null constraint |
| `neo4j:"name,fulltext"` | Add fulltext index |
| `neo4j:"name,text"` | Add text index |
| `neo4j:"name,point"` | Add point index |

## Schema Tags

### Index Tags

```go
type Person struct {
    neogo.Node `neo4j:"Person"`

    // Range index (default)
    Email string `neo4j:"email,index"`

    // Text index for prefix/suffix/contains queries
    Bio string `neo4j:"bio,text"`

    // Fulltext index for text search
    Description string `neo4j:"description,fulltext"`

    // Point index for spatial queries
    Location string `neo4j:"location,point"`
}
```

#### Index Types

| Tag | Neo4j Index Type | Use Case |
|-----|------------------|----------|
| `index` | Range | Equality, range queries (default) |
| `text` | Text | String prefix/suffix/contains |
| `fulltext` | Fulltext | Full-text search |
| `point` | Point | Spatial/geographic queries |

### Constraint Tags

```go
type Person struct {
    neogo.Node `neo4j:"Person"`

    // Unique constraint
    Email string `neo4j:"email,unique"`

    // Not null constraint
    Name string `neo4j:"name,notNull"`

    // Both constraints
    SSN string `neo4j:"ssn,unique,notNull"`
}
```

#### Constraint Types

| Tag | Neo4j Constraint | Description |
|-----|------------------|-------------|
| `unique` | Uniqueness | Property must be unique |
| `notNull` | Not Null | Property must exist |
| `nodeKey` | Node Key | Unique + Not Null (composite) |

### Composite Indexes/Constraints

Use a named index for composite indexes:

```go
type Person struct {
    neogo.Node `neo4j:"Person"`

    // Composite index: idx_Person_first_name_last_name
    FirstName string `neo4j:"first_name,index:idx_Person_name,priority:1"`
    LastName  string `neo4j:"last_name,index:idx_Person_name,priority:2"`

    // Composite unique constraint
    TenantID string `neo4j:"tenant_id,unique:unique_Person_tenant,priority:1"`
    PersonID string `neo4j:"person_id,unique:unique_Person_tenant,priority:2"`
}
```

The `priority` option controls the order of properties in composite indexes.

## Type Mapping

### Supported Go Types

| Go Type | Neo4j Type | Notes |
|---------|------------|-------|
| `string` | String | Direct mapping |
| `int`, `int8`, `int16`, `int32`, `int64` | Integer | Direct mapping |
| `uint`, `uint8`, `uint16`, `uint32`, `uint64` | Integer | Direct mapping |
| `float32`, `float64` | Float | Direct mapping |
| `bool` | Boolean | Direct mapping |
| `time.Time` | DateTime | Automatic conversion |
| `[]byte` | ByteArray | Direct mapping |
| `[]T` | List | Where T is supported |
| `map[string]T` | Map | Where T is supported |

### Pointer Types

Pointer types indicate optional properties:

```go
type Person struct {
    neogo.Node `neo4j:"Person"`

    // Required - will be empty string if missing
    Name string `neo4j:"name"`

    // Optional - nil if not present
    Nickname *string `neo4j:"nickname"`
    Age      *int    `neo4j:"age"`
}
```

### Custom Types

Types that implement the `Valuer` interface can customize serialization:

```go
type Status string

const (
    StatusActive   Status = "active"
    StatusInactive Status = "inactive"
)

// Status is automatically serialized as a string
type User struct {
    neogo.Node `neo4j:"User"`
    Status Status `neo4j:"status"`
}
```

## Embedded Structs

Embedded structs inherit their fields:

```go
type Timestamps struct {
    CreatedAt time.Time `neo4j:"created_at"`
    UpdatedAt time.Time `neo4j:"updated_at"`
}

type Person struct {
    neogo.Node `neo4j:"Person"`
    Timestamps               // Embeds CreatedAt, UpdatedAt
    Name string `neo4j:"name"`
}

// Person has: id, created_at, updated_at, name properties
```

<Aside type="caution">
If embedded struct fields conflict with parent fields, the parent field takes precedence.
</Aside>

## Complete Example

```go
type User struct {
    neogo.Node `neo4j:"User"`

    // Unique identifier (auto-indexed via Node.ID)
    // ID string is inherited from neogo.Node

    // Indexed for fast lookups with unique constraint
    Email string `neo4j:"email,unique"`

    // Required field with index
    Name string `neo4j:"name,notNull,index"`

    // Fulltext searchable
    Bio string `neo4j:"bio,fulltext"`

    // Optional field
    Phone *string `neo4j:"phone"`

    // Composite index with priority
    FirstName string `neo4j:"first_name,index:idx_User_fullname,priority:1"`
    LastName  string `neo4j:"last_name,index:idx_User_fullname,priority:2"`

    // Skip internal field
    PasswordHash string `neo4j:"-"`
}
```

## Auto-Migration

Schema tags are applied when you run auto-migration:

```go
// Register types
driver, err := neogo.New(
    "neo4j://localhost:7687",
    neo4j.BasicAuth("neo4j", "password", ""),
    neogo.WithTypes(&User{}),
)

// Create indexes/constraints from tags
actions, err := driver.Schema().AutoMigrate(ctx)
for _, action := range actions {
    fmt.Printf("Applied: %s\n", action.Description)
}
```

<Aside type="note">
Auto-migration only adds schema elements. It never removes indexes or constraints to prevent data loss.
</Aside>

## Best Practices

1. **Always use explicit tags**: Explicit property names prevent issues with Go naming changes
2. **Add schema tags**: Define indexes/constraints at the type level
3. **Use pointer types for optional fields**: Distinguishes "not set" from "empty"
4. **Use `neo4j:"-"` for computed/internal fields**: Keep internal data out of Neo4j
5. **Consider composite indexes**: For frequently combined WHERE clauses
